# Классы бизнес‑логики

В проекте реализованы два ключевых класса для работы с товарным каталогом:

-  Product — описание отдельного товара;
- Category — категория товаров с подсчётом статистики.

## Класс Product

Представляет собой модель товара в каталоге.

### Атрибуты

- name(str) — название товара (например, «Смартфон»).
- description(str) — подробное описание.
- price(float) — цена в рублях (с копейками).
- quantity(int) — количество единиц на складе.

### Пример создания

````

product = Product(

name="iPhone 15",

description="Смартфон Apple, 128 ГБ, чёрный",

price=89990.0,

quantity=15

)
````
### Особенности

- Все атрибуты обязательны при инициализации.
- Типы строго проверяются на уровне класса (рекомендуется использовать аннотации).
- Объекты Product передаются в список products класса Category.

## Класс Category

Описывает категорию товаров и ведёт автоматическую статистику по количеству категорий и товаров.

### Атрибуты экземпляра

- ````name(str)```` — название категории (например, «Смартфоны»).
- ````description(str)```` — описание категории.
- ````products(list\[Product\])```` — список объектов Product, относящихся к категории.

### Атрибуты класса (статистические)

- ````category_count(int)```` — общее число созданных категорий (увеличивается при \__init_\_).
- ````product_count(int)```` — суммарное количество товаров во всех категориях (учитывается при добавлении products).

### Пример создания

````
category = Category(

name="Смартфоны",

description="Мобильные телефоны и смартфоны",

products=\[product1, product2\] # список объектов Product

)
````
### Логика счётчиков

1.  category_count
    - Увеличивается на 1 при создании каждого нового объекта Category.
    - Позволяет отслеживать общее число категорий в системе.
2.  product_count
    - Увеличивается на len(products) при инициализации категории.
    - Суммирует количество товаров _во всех категориях_.
    - Например:
        - Категория 1: 5 товаров → product_count += 5
        - Категория 2: 3 товара → product_count += 3
        - Итого: product_count == 8

### Особые случаи

- ### Пустая категория (products=\[\]):
    - ````category_count```` увеличится на 1.
    - ````product_count```` не изменится (так как len(\[\]) == 0).

## Важные замечания

1.  ### Инициализация
    - Оба класса требуют передачи всех аргументов при создании.
    - Отсутствие аргументов вызовет ошибку.
2.  ### Типы данных
    - ````price```` — всегда float (даже если цена целая).
    - ````quantity```` — всегда int.
    - ````products```` — список объектов Product (не строк и не словарей).
3.  ### Счётчики
    - ````category_count и product_count```` — глобальные для класса.
    - Их можно сбросить вручную (например, в тестах):

````

Category.category_count = 0

Category.product_count = 0
````
1.  ### Использование в тестах
    - Для изоляции тестов рекомендуется сбрасывать счётчики перед каждым тестом.
    - Используйте фикстуры, для создания типовых объектов Product и Category.

## Пример совместного использования

\# Создаём товары

p1 = Product("iPhone", "Смартфон", 79990.0, 10)

# Архитектура системы

Система состоит из двух основных классов: `Product` и `Category`, которые взаимодействуют между собой для управления товарами и категориями.

---

## Класс `Product`

Отвечает за представление отдельного товара в системе.

### Основные характеристики

#### Приватные атрибуты
- `__price` — защищённое хранение цены товара.

#### Методы
- **Класс-метод `new_product()`**  
  Создаёт экземпляр `Product` из словаря (альтернативный конструктор).
- **Геттер `price`**  
  Возвращает текущее значение цены.
- **Сеттер `price`**  
  Включает валидацию:
  - Цена должна быть **строго положительной**;
  - При **снижении цены** запрашивается подтверждение от пользователя (например, через `input()` или логическое условие).

---

## Класс `Category`

Управляет группами товаров и обеспечивает целостность данных.

### Основные характеристики

#### Класс-атрибуты
- `category_count` — счётчик созданных категорий (все экземпляры).
- `product_count` — счётчик **всех объектов `Product`**, добавленных в любые категории.

#### Приватные атрибуты
- `__products` — защищённый список товаров (недоступен напрямую извне).

#### Методы
- **`add_product(product)`**  
  Добавляет товар в категорию:
  - Проверяет, что `product` — экземпляр `Product`;
  - Добавляет в `__products` через `append`;
  - Увеличивает `Category.product_count` на 1.
- **Геттер `products`** *(через `@property`)*  
  Возвращает строку в формате:
````
Название продукта, X руб. Остаток: X шт.
Название продукта 2, Y руб. Остаток: Y шт.
````

# Проект: Система управления товарами для интернет-магазина

## Назначение
Проект реализует объектно-ориентированную модель товаров для интернет-магазина с поддержкой категорий, валидации типов и операций над товарами.

---

## Задание 1. Создание классов-наследников

### Общая архитектура
Все товары наследуются от базового класса `Product`. Реализованы два специализированных класса:
- `Smartphone` — смартфоны;
- `LawnGrass` — газонная трава.

### Реализованные классы

#### 1. `Smartphone` (наследник `Product`)
**Дополнительные атрибуты:**
- `efficiency` — производительность (числовое значение);
- `model` — модель устройства;
- `memory` — объём встроенной памяти (ГБ);
- `color` — цвет корпуса.

**Особенности:**
- Наследует базовые свойства `Product`: `name`, `description`, `price`, `quantity`;
- Все атрибуты инициализируются в `__init__`.

#### 2. `LawnGrass` (наследник `Product`)
**Дополнительные атрибуты:**
- `country` — страна-производитель;
- `germination_period` — срок прорастания (строковое описание);
- `color` — цвет травы.

**Особенности:**
- Наследует базовые свойства `Product`;
- Подходит для товаров с агротехническими характеристиками.

#### 3. `````Product````` (базовый класс)
- Хранит общие свойства всех товаров (`name`, `description`, `price`, `quantity`);
- Используется как родитель для специализированных классов.

✅ **Принцип наследования:** повторяющиеся свойства вынесены в `Product`, что исключает дублирование кода.

---

## Задание 2. Ограничение сложения товаров

### Реализованная функциональность
Переопределён метод `````__add__````` для классов-наследников, чтобы:
- ✅ Разрешать сложение только объектов **одного класса** (например, `````Smartphone + Smartphone`````);
- ❌ Запрещать сложение разнотипных товаров (например, `````Smartphone + LawnGrass`````) с выбросом `````TypeError`````.

### Как работает
В `````__add__````` используется проверка:
````
if type(self) != type(other):
    raise TypeError("Можно складывать только объекты одного класса")
````

### Примеры:

- ✅ ````smartphone1 + smartphone2```` → новый объект ````Smartphone````;

- ❌ ````smartphone + grass```` → ````TypeError````.

## Задание 3. Валидация при добавлении в категорию
### Задача
Защитить метод add_product класса Category от добавления не‑товарных объектов.

### Решение
В методе add_product добавлена проверка:

````
if not isinstance(product, Product):
    raise TypeError("Можно добавлять только объекты класса Product или его наследников")
````
### Что проверяет
````isinstance(product, Product)```` — гарантирует, что объект является:

- экземпляром ````Product````;

- или наследником ````Product```` (например, ````Smartphone, LawnGrass````).

### Примеры:

- ✅ ````category.add_product(smartphone)```` → успешно;

- ✅ ````category.add_product(grass)```` → успешно;

- ❌ ````category.add_product("не товар")```` → TypeError.

## Ключевые технологии и приёмы
### Наследование

- ````Smartphone```` и ````LawnGrass```` наследуют ````Product````;

- Повторение кода минимизировано.

### Полиморфизм

- Метод ````__add__```` работает по‑разному для разных классов;

- Проверка ````isinstance```` позволяет обрабатывать наследников.

### Инкапсуляция

- Атрибуты задаются через __init__;

- Валидация типов на уровне методов.

### Обработка ошибок

- Использование raise TypeError для явного уведомления о нарушениях.

Миксин интегрирован в цепочку наследования класса Product, благодаря чему все производные классы автоматически получают данную функциональность.
